Installs agk, the command line, with Homebrew, Go or Docker, and asks before it changes anything. Read the script

The web console's workflow view. The graph and its agentiik.yaml are one object, edited either way: a step added in the graph is written in the file, a block written in the file is drawn in the graph, and Commit pushes the change.

mcp

Native MCP

An AI assistant connected to /mcp writes, validates, commits and runs workflows, with its user's permissions. A workflow can also be published as an MCP tool. From v0.7.0.

brick

Any image, any language

Each step runs in a fresh container, from any OCI image. A brick is an image with a manifest that declares its ports and parameters.

repository

Every workflow is a repository

agentiik.yaml at its root describes the graph. A push is validated before any branch moves, and each run records the commit it ran.

namespace

One installation, many people

Namespaces, groups and four roles decide who can read, run and edit each workflow.

From the command line or over MCP

Local CLI

agk runs the workflow against the Docker daemon of your machine. No server, no account.

Remote CLI

The same command line against a server: agk push sends the workflow, agk run starts it and follows it, agk status and agk logs read it back.

MCP

Connect an MCP client to your server's /mcp endpoint. The model learns the language, writes the workflow, validates it, commits it and runs it, as you.

Runs, in the web console

The console opens on every namespace you read together: what failed or waits on you first, a year of runs a square a day, then the latest runs, each with what started it and how long it took.
