The shape of the plan

The documentation says what Agentiik is; this page says in what order it becomes that, with no dates, estimates or capacity. It is rewritten rather than amended: an order survives being wrong, a schedule does not.

A milestone is a sentence that becomes true and stays true. A workflow runs to completion on one machine with no server is one. The graph evaluator is written is not: nothing outside the code can tell.

The links make the plan checkable against the specification, task by task. A task with no section behind it means a missing page or an unneeded task; both are worth finding out.

The closing fact governs: a milestone is crossed when its sentence is true, not when every task is ticked. A task that does not serve the sentence is dropped.

Why no dates

One maintainer cannot hold a calendar, and an order stays true at any pace while a missed date is simply wrong. A version marks sequence, not delivery, yet it is the real release: Agentiik carries one version across every repository, so the milestone v0.4.0 is the tag v0.4.0 everywhere. A date somebody waits on belongs on the repository milestones, next to the issues that move.

§

Why this order

Three rules fix the sequence. Everything else in it is negotiable.

  • The contract ships before anything that reads it. agentiik/schemas is released first, and again before each change, because it is the only cross-repository dependency for the workflow format. A format settled by whichever code consumed it first would be learnt slightly differently by the core, the console, the two applications and the workflow.language tool.
  • One path end to end before any width. v0.1.0 runs a whole graph on one machine before a server exists. What an envelope carries, what a brick receives and which port a rejected item leaves by are found by running a workflow, far more cheaply with no controller, task bus or runner around it.
  • Nothing multi-user before the permission model. Sharing, namespaces and roles land before the console, triggers and MCP, because each of those is a way in. A door added before the lock never quite closes: the path that worked before permissions existed stays open.

59 done

Makes possible: agk run --local takes an agentiik.yaml, runs its graph, and hands back the output envelopes. No server, no account, no database.

It puts the workflow language and the brick contract through real runs before anything depends on them (the second rule). Everything after it assumes both are settled; this milestone finds out where they are not.

The evaluator and the container driver are libraries, not internals, so that agk run --local is the code path a server run takes rather than a second implementation that drifts (figure). Makes possible: the four clients the documentation promised, on one model, and a project that knows what to do when a vulnerability arrives.

v1.0.0 adds no capability; it closes the scope. The mobile applications complete the clients, and the security work tests the threat model against the running thing. Disclosure must work before the number is handed out, because a version number is a claim others rely on.

Past v1

Out of scope for v1 is not a backlog: most of it costs more than it returns, after v1 as before. Three items differ, because the design already leaves their door open and closing it would be the mistake. The Helm chart, which Repositories names as later work rather than as a refusal, joins them.

DeferredWhat v1 already did for it
External identity providers: OIDC federation, SCIM provisioningThe principal model is provider-agnostic, so they touch authentication, not authorisation. That is why v0.3.0 was built the way it was.
Kubernetes as a substrateThe container driver sits behind an executor interface. A Job or Pod executor touches neither the controller nor the language.
A Helm chartFollows the executor above, in agentiik/deploy, shipped in the release it is ready for.
An external policy engine (OPA, Cedar)Roles and grants are evaluated in the API against the database. Delegating that is a substitution, not a redesign, as long as the permission vocabulary does not grow meanwhile.

The rest stays out: field-level permissions inside an envelope, authoring on mobile, hardware-level tenant separation, long-running bricks and continuous streams, loops in the graph, a public brick marketplace. Out of scope for v1 argues each, and the reasoning does not expire with the version number.
